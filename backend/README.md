# Backend Development Setup

This guide covers the FastAPI backend in `backend/`. Run the Python commands from that directory unless a command says otherwise.

## Prerequisites

- Python 3.12 or newer (the Docker image uses Python 3.12).
- Docker Desktop, with its Linux container engine running, for Docker Compose workflows.
- Git.

## Get the code and configure the environment

Clone the repository using your team's repository URL, then enter it:

```powershell
git clone <repository-url>
cd GymFlow
```

If you already have the repository, open its root directory instead. Create the root environment file:

```powershell
Copy-Item .env.example .env
```

Set `DATABASE_URL` in the root `.env` to your Neon PostgreSQL connection URL. Use the `postgresql+psycopg` driver and require TLS with `sslmode=require`. Do not paste credentials into documentation, source files, or Git. Keep `.env` on your machine; it must never be committed.

The development Compose stack requires `DATABASE_URL`. `BACKEND_CORS_ORIGINS` defaults to `http://localhost:3000`, and `NEXT_PUBLIC_API_URL` defaults to `http://localhost:8000`. The production-like Compose file uses `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB` for its own PostgreSQL container; it does not connect that container to Neon.

## Create a Python environment and install dependencies

From the repository root, create and activate a virtual environment in `backend/` with PowerShell:

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

If PowerShell blocks activation, use the Python executable directly at `.venv\Scripts\python.exe`, or adjust the current-user execution policy according to your organization's guidance.

Install runtime dependencies:

```powershell
python -m pip install -r requirements.txt
```

For development, install the development requirements instead; that file includes the runtime requirements, plus pytest, httpx, and Ruff:

```powershell
python -m pip install -r requirements-dev.txt
```

## Run the Backend

### Run locally with Python

From `backend/`, use Uvicorn and explicitly load the root `.env`:

```powershell
python -m uvicorn app.main:app --reload --env-file ..\.env
```

The API listens on port `8000`. Swagger UI is at <http://localhost:8000/docs>. The API routes use the `/api/v1` prefix, including the liveness endpoint at `/api/v1/health` and the database check at `/api/v1/health/db`.

### Run with Docker Compose

Run these commands from the repository root. The development stack starts the Backend and Frontend; it does not start a local database, so the Backend uses the configured Neon URL.

```powershell
docker compose up --build
```

To start only the Backend:

```powershell
docker compose up --build backend
```

The development stack publishes the Backend on `localhost:8000` and the Frontend on `localhost:3000`. Swagger UI is at <http://localhost:8000/docs>. Stop the stack with `docker compose down`.

`docker-compose.prod.yml` is a separate production-like stack. It starts Backend, Frontend, and a PostgreSQL 17 container; the database is internal to the Compose network and is not published to a host port. It uses the `POSTGRES_*` variables rather than Neon. It is not required for ordinary local backend development.

## Database and Alembic migrations

The development application uses Neon PostgreSQL. Alembic manages versioned schema changes using SQLAlchemy model metadata and migration revision files. The configuration is in `alembic.ini`; run Alembic commands from `backend/` so it finds that configuration.

Inspect the database's recorded migration revision:

```powershell
python -m alembic current
```

When migration revision files exist, apply them with:

```powershell
python -m alembic upgrade head
```

There are currently no migration revision files in `alembic/versions/`, so there is no project migration to apply yet. Do not run schema changes against the shared Neon database without following the team's review and deployment process.

After adding SQLAlchemy models, ensure their modules are imported by `app/models` so they register with `Base.metadata`. Then generate a candidate revision:

```powershell
python -m alembic revision --autogenerate -m "describe the schema change"
```

Open the generated file under `alembic/versions/` and review every operation manually before applying it. The current model metadata does not describe every table already present in Neon, so autogenerate may propose destructive drops. Never apply an autogenerated migration without checking it against the intended schema.

## Tests and code quality

Run the test suite and Ruff from `backend/`:

```powershell
python -m pytest
python -m ruff check app tests
```

The optional PostgreSQL integration test performs a read-only `SELECT 1`. It requires a dedicated test database. Set `TEST_DATABASE_URL` in the PowerShell session, then from the repository root run the test in the development Backend container:

```powershell
$env:TEST_DATABASE_URL = "postgresql+psycopg://USER:PASSWORD@TEST_HOST/TEST_DATABASE?sslmode=require"
docker compose exec -e TEST_DATABASE_URL backend python -m pytest -m integration
```

Replace the placeholders locally; never put real credentials in this guide. `TEST_DATABASE_URL` must point to a separate test database, never the shared Neon application database. The integration test also refuses to query when its host, port, and database match `DATABASE_URL`. The development Compose Backend must be running first.

## Backend structure

- `app/api/` — FastAPI routers and HTTP endpoints.
- `app/core/` — application settings and shared core configuration.
- `app/db/` — SQLAlchemy base, engine, sessions, and database dependency.
- `app/models/` — SQLAlchemy model modules, imported here as they are added.
- `alembic/` — migration environment, templates, and versioned migration files.
- `tests/` — API, database session, and optional PostgreSQL integration tests.

## Troubleshooting

- **Compose reports that `DATABASE_URL` is missing:** confirm the root `.env` exists and contains a valid `DATABASE_URL`. Compose reads this file from the repository root.
- **The API cannot connect to Neon:** check the hostname, database name, network access, and TLS requirement (`sslmode=require`). Do not share the connection URL in logs or chat.
- **Docker commands cannot reach the engine:** start Docker Desktop and wait until its Linux container engine is ready.
- **A Python package or module is missing:** activate `backend/.venv` and install `requirements-dev.txt` for development. Check that Python 3.12 or newer is selected.
- **Alembic cannot find its configuration or reports no head:** run it from `backend/`. There are currently no migration revisions, so `upgrade head` has nothing to apply until a reviewed revision is added.
- **Autogenerate proposes dropping existing tables:** the SQLAlchemy metadata may not include all existing Neon tables. Review the generated revision manually and do not apply unintended drops.
